### How it was measured

Everything marked "measured" below comes from these runs, on darwin/arm64 with Apple clang 21.0.0
and Go 1.27.4 (the default pure-Go build; C++ ran its `arm64` kernel):

- **`make oracle` at both pins**, in a throwaway worktree. At `v5.0.2` it reproduces the
  committed files byte for byte. At `v5.1.1`, `git diff --stat testdata/` is
  `testdata/ondemand/oracle.jsonl | 1974`, `testdata/stream/oracle.jsonl | 292`
  (1133 insertions, 1133 deletions): **987 of 30,715** On-Demand cases and **146 of 2,911**
  stream cases record a different output.
- **Go at `HEAD`** passes `TestOracle` and `TestStreamOracle` against the `v5.0.2` files and
  fails exactly those 987 and 146 cases against the `v5.1.1` files. With the `v5.1.1` files,
  `go test -short ./...` fails nothing else. So for every recorded case, "Go today" is the
  `v5.0.2` result. (Four DOM `CommaDelimitedArray` cases are compared only up to where C++
  `v5.0.2` read past its end; package 13 lists them.)
- **Attribution by build.** `oracle.cpp` was built against `include/` and `src/` of `BASE` and
  of each of the 73 commits that touch those directories, and all 33,626 cases were run at each.
  The builds at `BASE` and `TARGET` give the same output as the single-header builds. Nine
  commits change at least one case; the other 64 change none. Every changed case is attributed:
  35 cases change at more than one commit, none changes and changes back.

  | Commit | On-Demand cases | Stream cases |

  | `d71b2fca` | 26 | 0 |
  | `b35f05d0` | 0 | 49 |

- **Inputs from the commits' tests and bodies** that the recorded cases miss were run through
  the `BASE` and `TARGET` oracle binaries, one process per case so that a crash is a result, and
  through Go at `HEAD` with the test suite's own `runScript` and `streamOut`.
- **Inputs the oracle's script language cannot express** (reads that go on after an error, a
  key read after its value, batch sizes, threads, development checks) were run through a
  scratch C++ program against both single headers, and through a scratch Go test.
- **The DOM.** `dom::parser::parse`, `minify(element)` and `minify(buf)` give the same error
  code and the same output at `BASE` and `TARGET` for all 4,625 distinct documents of the
  oracle cases (812 of them parse). No package changes `Parse`.

Not measured: C++ on input whose padding is not zero (the oracle uses `padded_string`); the
`amd64`, `purego` and NEON Go builds; any Go speed.

## Package 12: `JSONSequence`: an unclosed string keeps its record's RS

Read `AGENTS.md` first. This is a stream change.

**Upstream:** b6b32f1e (#2980) from simdjson v5.0.2..v5.1.1.

**C++ before and after:** When a `json_sequence` stream ends inside a string, stage 1 dropped
the last structural index, taking it for the string's opening quote. A string record written
`RS"…` has its quote right after the RS, and the scanner reads RS as a scalar byte, so the last
index is the RS: the record marker was dropped and the dropped region started at the RS. Now the
RS is kept and the scan stops at the quote, so `truncated_bytes()` counts from the quote.

**Inputs:**

| Input (bytes, verbatim) | API, script | C++ v5.0.2 | C++ v5.1.1 | Go today |
|---|---|---|---|---|
| `\x1e"` (stream cases 1482, 1483) | `ParseMany`; `IterateMany`, `walk` | `~2` | `~1` | `~2` |
| `\x1e"a\"b"\n\x1e"` (hex `1e22615c2262220a1e22`; cases 1498, 1499) | `ParseMany` | `@1 h22615c226222 wsa"b ~2` | `@1 h22615c226222 wsa"b ~1` | as v5.0.2 |
| `\x1e1\n\x1e2\n\x1e"abc` | `ParseMany` | `@1 h31 wi1 @4 h32 wi2 ~5` | `@1 h31 wi1 @4 h32 wi2 ~4` | as v5.0.2 |
| `\x1e1\n\x1e2\n\x1e"abc` | `IterateMany`, `walk` | `@1 h31 i1 @4 h32 i2 ~5` | `@1 h31 i1 @4 h32 i2 ~4` | as v5.0.2 |
| `\x1e[1,23\x1e]\n\x1e"open` + 1 space (case 1023) | `IterateMany`; `find b`, `walk` | `@1 h5b312c32331e5d x17 @7 h5d0a1e226f70656e20 x17 ~7` | `@1 h5b312c32331e5d x17 @7 h5d0a1e226f70656e20 x17 ~6` | as v5.0.2 |

In Go terms, `~N` is the final `*StreamError` with `ErrTrailingContent`: its `Offset` is
`len − N`, so it moves from the RS to the quote.

**Go owner:** `Reader.finish` in `internal/stream/stream.go` (the `held` index and `scanLen`
when the input ends in an unclosed string), with `take` and `push`, which hold the last index
back.

**Change:** In a `JSONSequence` stream that ends inside a string whose opening quote directly
follows its RS, the dropped tail starts at the quote, not at the RS: the final
`ErrTrailingContent` reports the quote's offset.

**Evidence to add:** none needed: 24 recorded cases cover it. One more for `gen.py`'s `PINNED`:
white space between the RS and the quote (`\x1e` + 2 spaces + `"abc`), which is unmeasured here.

**Spec and quirk records:** streams spec §5.3, "End of input" ("drop a trailing
unclosed-string quote"): say what is dropped when the last index is an RS.

**Left out:** the same fix in `json_sequence_partial` (batches before the last, `CAPACITY`),
which Go does not port (streams spec §4.3).

**Done when:** stream cases 524, 824, 1023, 1482-1491, 1498-1501, 2046, 2048, 2532, 2534, 2536, 2538, 2540 pass (24);
`TestStreamOracle`, `make fuzz target=FuzzParseMany`, `make fuzz target=FuzzIterateMany`.
